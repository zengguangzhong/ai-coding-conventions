# 编码原则

所有 AI 编码工具共享的核心编码纪律。

---

## 先思考再编码

凡事先 Plan 再动手，不直接写代码。

- 明确陈述假设，不确定就问
- 存在多种解释时列出来，不默默选一个
- 复杂任务先制定计划，简单任务至少说明思路
- 前提不确定时停下来确认，不跳步推进

## 简洁优先

用最少代码解决问题，不添加推测性内容。

- 能用现成方案就不自造
- 能写简单逻辑就不用复杂抽象
- 不添加未被要求的特性、灵活性或可配置性
- 不为不可能的场景添加错误处理
- 如果 200 行代码本可以是 50 行，重写

## 精准变更

只改必须改的，不动周边。

- 不重构相邻代码或没坏的部分
- 匹配现有风格，即使你会用不同方式处理
- 清理因变更产生的孤儿 import/变量/函数
- 除非被要求，不移除预先存在的死代码
- 每行变更应可追溯到明确的需求

## 目标驱动执行

定义可验证的成功标准，循环验证直到通过。

- "添加验证" → 写测试 → 让测试通过
- "修复 bug" → 写重现测试 → 让测试通过
- "重构 X" → 确保重构前后测试均通过
- 检查修改是否实际生效
- 确认功能符合预期，无引入新问题

## 验证前提，逐步推理

前提不对，后面全白费。

- 每步推理前显式列出依赖的假设
- 确认假设成立再往下走
- 无法验证的前提明确说出来：这一步我假设了 X，如果 X 不成立，结论是……

## 文档用中文

README、注释、commit message 等项目文档一律中文，技术术语保留英文。

## 修改配置前查文档

修改任何工具/框架配置文件前，先查阅官方文档。不靠经验或直觉猜测。
